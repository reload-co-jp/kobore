# 「こぼれことば」Webメディア 仕様書

## 1. プロジェクト概要

URL:

https://kobore.reload.co.jp

サイト名：

**こぼれことば**

コンセプト：

> 言葉からこぼれた、もうひとつの意味。

「略語」を単純に集めるサイトではなく、**元の言葉・名前の一部分だけが切り出され、その部分が独立した言葉として使われるようになった現象**を記録・解説するWebメディア。

たとえば、

* キログラム → キロ
* ギガバイト → ギガ
* 携帯電話 → 携帯
* インターネット → ネット
* Mrs. GREEN APPLE → ミセス
* 千原ジュニア → ジュニア

などを扱う。

単なる「何の略？」ではなく、

**どこからこぼれたのか**
→ **どういう意味だったのか**
→ **どう独立したのか**
→ **現在はどんな意味で使われているのか**

を、出典とともに解説する。

---

# 2. サイトの基本方針

以下を最重要コンセプトとする。

### 「略語辞典」にはしない

以下のような単純な略語は主役にしない。

* パソコン
* コンビニ
* ファミレス
* リモコン
* ヒゲダン

これらは複数の部分を組み合わせた一般的な略語であり、「一部分がこぼれて独立した」というサイトコンセプトから外れる。

特に優先するのは以下。

### A. 単語の一部分が独立

```text
キログラム
  ↓
キロ
```

### B. 接頭辞・接尾辞などが独立

```text
ギガバイト
  ↓
ギガ
```

### C. 固有名詞の一部分が独立

```text
Mrs. GREEN APPLE
  ↓
ミセス
```

```text
千原ジュニア
  ↓
ジュニア
```

### D. 独立後に意味が変化・拡張したもの

```text
ギガ
↓
SI接頭語
↓
ギガバイト
↓
通信データ容量
```

単に短くなっただけではなく、**独立後に別の意味・対象を持つようになったものを特に高く評価する。**

---

# 3. サイトの性格

辞書ではなく、**言葉の変化を読むメディア**として設計する。

重視するもの：

* 語源
* 歴史
* 意味の変化
* 用法
* 世代による違い
* 固有名詞から一般名詞への変化
* 技術用語から日常語への変化
* 実際の使用例
* 出典

記事を読んで、

> 「そういうところから、今の意味になったのか」

と思えることを目標とする。

# 7. 分類

JSONの `classification` は固定値として管理する。

```text
part_extraction
independent_usage
meaning_shift
semantic_expansion
semantic_narrowing
proper_noun_origin
generalization
reanalysis
```

意味：

| ID                 | 意味                |
| ------------------ | ----------------- |
| part_extraction    | 元の語の一部分が切り出された    |
| independent_usage  | 切り出された部分が単独で使われる  |
| meaning_shift      | 意味が変化した           |
| semantic_expansion | 意味が広がった           |
| semantic_narrowing | 意味が狭くなった          |
| proper_noun_origin | 固有名詞由来            |
| generalization     | 特定対象から一般的な対象へ広がった |
| reanalysis         | 使用者による再解釈が起きた     |

---

# 8. 除外・低優先度分類

以下のようなものは原則として優先しない。

```text
compound_abbreviation
initialism
acronym
multiple_part_extraction
```

たとえば、

```text
リモコン
リモート + コントロール
```

のようなものは、「一部分がこぼれて独立した」というより複数箇所を組み合わせた略語なので低優先度とする。

# 11. 歴史情報の扱い

「最初に使われた」と断定しない。

以下を明確に区別する。

```text
初出
```

と

```text
現時点で確認できる最古の用例
```

十分な資料がない場合は、

> 現時点で確認できる範囲では……

などと表現する。

また、

* 語源
* 略語としての成立
* 独立語としての成立
* 意味変化

を混同しない。

---

# 12. 用例データ

実際の用例と作成例を明確に区別する。

```json
{
  "text": "今月はギガが足りない。",
  "type": "constructed"
}
```

`type` の例：

```text
historical
newspaper
magazine
book
web
official
sns
conversation
advertisement
constructed
```

`constructed` はサイト側で作成した例文。

実在する用例を掲載する場合は、必ず出典を紐付ける。

# 18. 記事本文

各記事では以下を説明する。

### 1. 何からこぼれた？

元の言葉・名前を説明。

### 2. 元々どういう意味だった？

元の意味・用法を説明。

### 3. いつ独立した？

確認できる資料をもとに説明。

### 4. 意味は変わった？

元の意味と現在の意味を比較。

### 5. 今はどう使われる？

現在の使用場面を説明。

### 6. なぜ定着した？

可能な場合は社会的・技術的背景も説明。

* 白を基調
* 大きなタイポグラフィ

# 39. 重要な編集方針

このサイトで最も重要なのは、**「略語なら何でも載せる」ことを避けること。**

掲載基準は、

> 元の言葉の一部分が切り出され、その部分が独立して使われるようになったか？

を第一条件とする。

さらに、

> 独立したことで意味や指す対象に変化が生じているか？

を高く評価する。

そのため、

```text
元の言葉
↓
一部分がこぼれる
↓
独立して使われる
↓
意味・対象が変化する
```

という流れが説明できる言葉を優先する。
